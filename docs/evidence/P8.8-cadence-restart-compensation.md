## Implemented boundary

The API runner now resumes cadence from the latest valid recovery point instead of resetting the full interval on every process start.

- Storage exports the restore path's existing strict, read-only manifest/database bundle admission: canonical timestamp, exact manifest shape, QA Hub application ID/schema, size/SHA, integrity, and foreign keys.
- The runner scans only direct `rpo/*.sqlite.manifest.json` entries and derives each corresponding primary `.sqlite`; `.sqlite-shm` and `.sqlite-wal` are ignored.
- Manifest and database must be ordinary files whose real parent remains the canonical `rpo` directory. Any invalid candidate fails startup; the runner never falls back to an older point.
- A recovery timestamp more than 60 seconds in the future fails closed; a smaller clock skew is conservatively treated as age zero.
- With cadence enabled and explicit on-start disabled, no recovery point or a stale point triggers one worker-owned backup before listen. A fresh point schedules the next backup for `interval - age`.
- A single stopped-aware timeout replaces the old fixed interval callback. Shutdown clears it and drains the same active worker backup before worker close.
- No backup, manifest, sidecar, or other file is deleted.
