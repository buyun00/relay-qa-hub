## One bounded real fault

The independent API started in explicit debug auth mode against an isolated copy containing `LOCAL-1`. After readiness, a separate `node:sqlite` connection acquired `BEGIN IMMEDIATE` on the same database and held the write lock while the controller sent one real request:

```text
POST /api/v1/bugs/01402518-c3b8-4e88-86c8-650983e64048/comments
clientSubmissionId = 2d396842-024b-4614-9e4f-b70cd96f021a
Idempotency-Key = comment:<bugId>:<clientSubmissionId>
X-Correlation-ID = <clientSubmissionId>
```

The request returned HTTP `500` after `264.154 ms`; it never returned `201`. The API live endpoint still returned `200`. While the lock was still held, direct reads in the isolated database found for the new UUID:

- `comments`: `0`
- `events` limited to the correlation ID, `comment.created`, and `resource_type=comment`: `0`
- `submissions` limited to `comment_append`: `0`

This proves the failed transaction did not partially commit or consume the submission identity.

The lock transaction was rolled back and the connection closed. The controller then sent the exact same HTTP body, client submission ID, idempotency key, and correlation ID. It returned `201` in `10.012 ms`, with Comment `cbdef755-80ea-4b45-b901-4a8ebda61f6b` and the same correlation ID. Direct readback then found exactly one Comment, one matching Event, and one Submission.

The exact API child was reaped and port 4320 was closed. The bearer existed only in controller/child memory and was not printed or committed. The one-use controller was removed. No production/default busy timeout, Web, Android, Electron, Relay, Unity, or Jenkins state was changed.
