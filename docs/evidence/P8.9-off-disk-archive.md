## Implemented boundary

The existing API-owned backup runner can now optionally archive a strictly validated recovery point. Archiving is disabled by default and has no configured drive by default. Enabling it requires both the normal backup runner and an explicit absolute `QA_HUB_BACKUP_ARCHIVE_ROOT`.

- The runner continues to use its single existing `SqliteStorageWorker`; there is no second database writer or archive scheduler.
- The source database and exact `.manifest.json` sidecar must first pass the restore path's size, SHA-256, QA Hub application ID/schema, integrity, and foreign-key admission.
- Archive, backup, data, database, evidence, quarantine, and optional source roots must not overlap after canonical resolution. The original archive path is retained so a junction/symlink path fails closed before archive creation.
- Only the manifest-bound primary `.sqlite` and its exact manifest are copied. The primary file uses create-only copy, is checked for size and SHA-256, and the manifest is published last with create-only semantics.
- A valid existing pair is an idempotent `existing` result. A partial or mismatching target fails closed; the implementation never overwrites, deletes, or performs retention cleanup.
- A fresh cadence recovery point is archived before API listen; a newly created on-start or cadence backup is archived before its operation is reported successful.
