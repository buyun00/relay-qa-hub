## Explicit non-blocking follow-up

- Room persists the final attachment reservation/claim receipt, but does not yet checkpoint every
  upload stage for process-kill/resume or response-loss reconciliation.
- The current Android client sends one chunk. The server keeps screenshots up to 8 MiB as one
  chunk; larger media still needs multi-chunk/resumable upload.
- The MuMu smoke accepts a valid PNG magic as `clean` and writes debug plaintext Blob storage.
  Production scanner/encryption/atomic-file/orphan cleanup remains required before a release Gate.
- Frozen durable HTTP idempotency receipts need a narrow additive migration because the existing
  privacy trigger rejects upload `sessionId`; this slice relies on typed uniqueness/natural replay.
