# Android 0.1.15：游戏 APK 快速下载兼容新目录

## 问题与改动

旧客户端默认读取 `http://10.100.5.129:8000/apk/?json=true` 的平铺列表；2026-09-11 实查旧目录最新为 2.1.170，而新目录已有 Android Debug / Release 2.5.1，因此旧入口漏掉新版安装包。

新版默认读取 `http://10.100.5.129:8000/ozdqp/Android/{Debug|Release}/`，同时兼容目录服务的 `版本/构建号` 折叠显示和普通分层目录。两种配置各取最新五个 APK，按数值版本和构建号倒序，显示配置、版本、构建编号。先验证对应构建的 `build-info.json` 已 ready，且平台、配置、版本、构建号、产品渠道和源码身份匹配，再派生当前目录下的 APK 地址；不使用清单中任意外部 URL。

只列出安装 APK，AAB、IPA、热更 ZIP 和没有 APK 的纯资源构建均跳过。下载继承现有流式进度与系统安装器交接，新增清单 SHA-256 核验以避免同名包混用。明确自定义的旧 `/apk/` 配置仍可使用，默认新目录失败时不会退回旧目录并把旧包当作最新。

文件服务器可能关闭闲置连接；元数据和 APK 的只读 GET 客户端启用连接故障恢复，避免复用断开的连接时立即报下载失败。账号登录等写请求仍使用原客户端配置。HTTP 测试先建立连接，再主动断开下一次目录读取，验证自动恢复后列表一致。

## 验证

- 单元测试 75 项通过；新增目录折叠/展开、数值排序、清单与目录不匹配、未完成构建、路径越界、hash 缺失、只选 APK、纯资源版本跳过及 HTTP 两配置读取验证。
- `lintDebug` 通过，无错误；构建通过。设备验证使用保留的独立 MuMu 实例 1（ADB 16416），主实例 0（ADB 16384）的并行预览应用和草稿不操作。
- 最终发布、真实下载、安装入口与升级保留收据位于 `work/android-0.1.15-release/`。

该更新是 QA Hub 安卓客户端版本 0.1.15-debug / versionCode 16。游戏 APK 版本继续使用构建机实际版本，二者不混用。
