## Defensive database invariants

The schema and real-DML regression suite enforce, among other facts:

- Account, User, Device installation, native session, refresh family/token,
  and service-principal lifecycle changes are one-way exact version-CAS facts.
  Disabled or revoked parents cannot be resurrected to mint a new session or
  retain machine-event authority.
- Native auth timestamps are server-clock bounded; personal refresh lifetime
  cannot exceed 30 days; future-issued tokens cannot become active early; auth
  response-loss replay binds the exact current session and token generation.
- Generic idempotency excludes native secret responses, anchors reservation
  TTLs to the server clock, recursively rejects restricted JSON keys, and binds
  committed typed operations to the byte-exact immutable submission response
  plus its exact audit event.
- Comments begin at version one and are immutable/append-only. Bugs require an
  exact optimistic-lock version increment and monotonic `updated_at`; identity,
  project number/key, reporter, and creation facts remain immutable.
- Upload attempts serialize one exact tuple. Chunks, leases, terminal uploads,
  Blobs, Attachments, and claimed bindings cannot be rewritten or resurrected.
  Only the exact finalized ready/clean upload can be reserved and claimed.
- Capture method outcomes and Poco snapshots are append-only. Enrichment starts
  effect-free as `attempted=0/status=unavailable/version=1`, then advances via
  exact CAS. Bundle finalization requires the `qa.snapshot` method outcome,
  typed capture artifact, and bounded snapshot fact to agree exactly.
- Build provenance, manifest commits, BuildRequirement decisions, repair links,
  Verification evidence, Relay receipts, external typed events, and attachment
  links retain their account/project/Bug/Attempt/Build identity.
