# UX focus verification - 2026-08-26

## Outcome

The current Web and Android clients implement the focused usage feedback without
changing QA Hub ownership, Relay authority, or the shared API/database.

- A Bug has one user-facing content value. The legacy API title is an internal
  content-derived summary only.
- Web uses a large centered detail dialog, prominent content and images, sticky
  workflow actions/status, 16 px list primary text, and an in-page image viewer.
- Android has a unified Bug home with `我提交的` / `项目全部`, clickable details,
  floating-ball controls and the `整个屏幕` instruction. The second destination is
  the single-content create flow.
- Android form scrolling never draws. A screenshot is a passive preview until it
  is tapped, then a full-screen editor provides draw, undo, clear, save and
  cancel.
- The verifier defaults to the current identity. The fixer defaults to that
  identity's last successful choice, with latest submitted Bug as migration
  fallback.
