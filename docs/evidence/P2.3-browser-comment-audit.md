to match, passes the authenticated browser principal into the Comment/Event routes, and persists that

## One informative audit failure

The disposable SQLite copy received a temporary trigger named
`p23_forced_comment_audit_failure`, scoped only to `BEFORE INSERT` of `comment.created`. Before the
request, the copied database had totals of two Comments, two `comment.created` Events and two
`comment_append` submissions.

The same authenticated browser submitted a second, uniquely labelled Comment. The API returned
`500 ERR_SQLITE_ERROR`, and the Web kept the typed body visible while reporting the failure. Its
timeline remained at two items with no additional `comment.created` entry.

The post-failure database check was:

```json
{
  "comments": 2,
  "commentEvents": 2,
  "commentSubmissions": 2,
  "failedBodyComments": 0,
  "integrity_check": "ok"
}
```

This proves the worker's existing `BEGIN IMMEDIATE` transaction rolled back the preceding Comment
insert when the audit append failed; the API did not return false success. The temporary trigger was
then removed, its remaining count was verified as zero, and `integrity_check` remained `ok`.
