# Android uncertain create recovery — source verification

The bounded source fix preserves the original creation intent after four retryable failures. It does not assign a replacement Bug/attachment identity when the user retries an uncertain result. The existing `FAILED_PERMANENT` state plus `RETRY_EXHAUSTED_` error marker is reused; no Room schema or persisted enum changed.

`UnconfirmedCreateSubmission` and the actual DAO update rearm only the original row under account/project/actor/installation/session. `PendingBugSubmission` stores that full scope, the original request, and the queued operation ID. Ordinary same-person login derives the same queue scope. A changed scope or a missing known queued row fails closed. A crash before Room insertion can recover only the saved request. Current form edits cannot replace it.

`commitDurableBugDraft` retains staged media once a persistent intent may reference it, and after Room insertion. A scheduling or subsequent preference failure cannot delete queued images. Form text is saved synchronously and is no longer cleared just because enqueue succeeded. A matching server receipt clears unchanged text only when the form is closed and no captured image needs conservative preservation.

Capture ID equality does not prove annotation equality. Captured drafts are therefore kept conservatively; an open new-Bug form is not reset by a receipt, and retry does not navigate away from its annotation editor. Pending captures cannot be explicitly deleted until the original submission is confirmed. The retained-draft message says a subsequent explicit submit creates a new Bug; that new intent receives new IDs. This does not implement persistent unsaved annotation-editor strokes across manual navigation or process death.

Legacy code22 records are inspected before allocating a new creation identity. An existing capture sidecar selects its original full-scope request; a foreign-scope row fails closed. Pure-text recovery considers every unresolved create row and first records an explicit recovery choice instead of assuming the current form matches a latest row. Only an exact scoped success receipt resolves the old intent. Generic permanent classification alone never permits a replacement ID.

The explicit **“保留附件失败记录，允许修改后新建”** action is limited to a durably unpromoted attachment-stage row with an exact local size/hash rejection or upload-stage HTTP 400/413/415/422. This proves that Bug POST has not occurred; partial uploads may exist. Before releasing the pending slot, a checked preference commit retains the original pending request, complete failed-row snapshot and full-row fingerprint. Room records and original media remain. Changed row contents invalidate the release proof. Failed preference commits cannot release the intent, including the modeled case where preference memory changes before the disk commit returns false. No CREATE_BUG failure can use this escape path.

The separate **“使用原请求重新确认”** button handles only non-201 2xx status errors and the two success-receipt scope errors. It atomically rearms the same complete-scope operation/key. Ordinary resume and automatic queue execution leave these permanent failures unchanged. The original payload and attachment identities are retained, and the existing exact-201 and receipt-scope validators still apply. A still-invalid response remains unconfirmed; fixing the service alone does not trigger a replay. Generic HTTP 4xx, `INVALID_QUEUED_REQUEST` and other unreviewed errors have no new release or retry authority.
