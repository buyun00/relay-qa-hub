# QA Hub v2.1 用户自测移交清单

记录日期：2026-09-10。以下项目已按用户决定移交用户执行，代理未执行，也不记为 PASS。建议只使用 v2.1 隔离实例（API `4639`、Web `4640`、server MCP `4641`、local MCP `4642`）、独立测试项目和独立外部目标；不要把 `4319/4174/4320` 或日常客户端作为写入目标。

## 共用留证

每项至少保存：项目 ID、人员 ID、组件键与配置版本、请求或幂等键、外部任务 ID、关键状态时间线、最终 UI 截图、HTTP 或 MCP 回读、外部终态回读、产物文件名/字节数/SHA-256。凭据只保存引用名，不把口令、令牌、Cookie 或二维码内容写进证据。

## 物理 Android 真机

- **入口**：安装隔离预览包 `com.relayqahub.android.preview.debug`，按项目入口和姓名登录；使用“悬浮球”、新建 Bug、Bug 详情及“检查更新”。
- **配置/产物**：code `28` / `0.2.0-preview.15`，APK SHA-256 `61a885f22b9a62383d923bf36ca0f9ade9f987c22bb30c7323bd8acbd7536e7a`；设备需能连接隔离 API，不能回连生产。
- **预期**：MediaProjection 截图进入未提交草稿；断网提交保留字段和图片，恢复后只生成一个 Bug 和一张最终收据；应用内升级保留姓名、项目、Bug、草稿和媒体；日常包仍可独立使用。
- **边界**：不要卸载、清应用数据、改 Room/SQLite、手工重提或用 `adb install` 代替应用内升级结果。若失败，保留 App 数据、媒体、Room 数据库及 WAL/SHM，并记录错误和可见重试入口。
- **代理侧参考**：MuMu 已从 code 27 经应用内入口和系统安装器升级到 code 28，并保留项目、姓名、Bug、截图草稿和 daily 包；这只作为模拟器参考，不替代本项物理真机自测。见 [`android/acceptance/android-code28-self-update/luna-e2e/058-verdict.md`](android/acceptance/android-code28-self-update/luna-e2e/058-verdict.md)。

## 真实打包

- **入口**：GM 在“项目管理 → 组件设置”配置并启用 `build`；员工从“打包下载 → 打包 → 仅打包”发起，也可从同项目 HTTP/MCP 入口发起并回读。
- **配置**：专用 Jenkins 地址、Job、下载源、增量 ZIP 路径、含 `{buildNumber}` 的产物地址模板、凭据引用名及预设 JSON。
- **预期**：QA Hub 记录从排队号进入真实构建号和终态；下载到本次独立产物，文件字节数和 SHA-256 与 Jenkins 端一致；项目、组件版本和提交人可回读。
- **边界**：`queued`、HTTP 200、监听存在或构建日志结束均不等于通过；必须取得终态和本次产物。

## 单次打包上传

- **入口**：先配置并启用 `build`、`upload.incremental` 和 `build_upload.single`；在“打包”下拉选择“打包并上传增量”。
- **配置**：除打包配置外，还需独立上传账号、产品、渠道、目标前缀、测试/正式解压目录前缀、上传凭据引用及 `buildPreset`。
- **预期**：同一链路记录精确构建号、ZIP 身份、上传 job ID 和最终远端发布结果；客户端退出后服务端仍继续，重新打开可从组件历史回读。
- **边界**：`upload_started` 或上传进度 100% 不是发布终态；未知提交结果先用原 request ID 查询，不能直接重复发起。

## 真实增量上传发布

- **入口**：“上传增量”页选择已有 Android 增量包或 iOS ZIP，完成测试信息后执行发布；同步核对“组件历史”及同项目 HTTP/MCP 结果。
- **配置**：`sourceUrl`、`apiBase`、`loginBase`、`targetPrefix`、`testDirectoryPrefix`、`releaseDirectoryPrefix`、`credentialRef`，以及产品、渠道、归属名、测试人等 defaults。
- **预期**：来源 ZIP 的字节数、修改时点和 SHA-256 固定；任务完成测试解压、测试结论绑定及正式发布；最终回读 `published=true` 且 `remoteStatus=100`，远端文件与目标路径可核对。
- **边界**：文件变化、账号变化或结果未知时保留原任务和 request ID；不要重建任务掩盖失败阶段。

## Relay AI 制作交付

- **入口**：GM 启用 `relay.production`；从 Bug 详情“可选：交给 Relay”或 Relay 制作页创建/继续任务，再从“组件历史”查看交接、批次和暂停恢复。
- **配置**：专用 Relay 地址、目标实例 ID、外部项目 Key、测试凭据引用和回调配置；工作区及分支必须与生产隔离。
- **预期**：QA Hub、Relay 项目、Bug、attempt、handoff 和 task 映射一致；真实交付回执证明 `pushed=true`、`verified=true`、`commitSha=remoteSha`；交付只能推进到待构建/待验收，不能自动通过验收或关闭 Bug。
- **边界**：`accepted=true`、任务已创建或 callback 已到达都不是交付完成；需读取远端分支/提交和 QA Hub 持久化回执。

## 第三方同步和轻语闭环

- **入口**：GM 启用 `qingyu.sync`；从“从轻语导入 Bug”扫码连接测试账号，选择明确项目和缺陷导入；QA Hub 人工验收关闭后核对同步，失败时使用原入口或 `qa_resolve_qingyu_bug` 明确重试。
- **配置**：第三方服务地址、外部项目 ID、测试凭据引用；只用获准修改的测试账号、项目和订单。
- **预期**：导入后 QA Bug 与第三方 defect ID 持久关联，标题/说明和项目正确；QA Hub 关闭后第三方状态回读为已解决；同步失败不改变 QA Hub 已完成的人工验收事实，并保留可重试记录。
- **边界**：扫码成功、列表刷新或本地 link 存在不等于闭环；必须回读第三方最终状态。不要用生产订单证明测试。
