## Implemented boundary

The independent API now owns an optional online-backup runner that calls `createOnlineBackup()` on its existing `SqliteStorageWorker`. It does not create a second SQLite worker or writer and does not expose an HTTP restore route.

- `QA_HUB_BACKUP_ON_START` defaults to `false`.
- `QA_HUB_BACKUP_INTERVAL_MINUTES` is optional and accepts 15 through 10,080 minutes.
- Enabling either mode requires an absolute `QA_HUB_BACKUP_ROOT` independent from data, database, evidence, quarantine, and configured source roots.
- Existing paths are resolved through `realpath`; backup root and its direct `rpo` child must be ordinary directories, not symlinks or junctions.
- The runner generates a canonical UUID filename, rechecks target containment, and uses the storage layer's create-only database and manifest writes.
- On-start backup completes before the API listens. Shutdown clears cadence first and waits for any active backup before closing the same worker.
- No retention deletion is implemented.
