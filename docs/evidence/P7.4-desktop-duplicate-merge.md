## One key failure

An authenticated, direct call attempted to mark `LOCAL-3` as a duplicate of itself at its exact version. The API log recorded one real response:

```text
POST /api/v1/bugs/ef1e540d-1afc-4796-8655-daf784094e60/mark-duplicate -> 422
```

The route maps `422` only from the storage `GUARD_FAILED` result. Windows PowerShell 5 exposed the HTTP status but did not preserve the JSON error body in this bounded harness; the response body is therefore not claimed as observed. SQLite proved the failed attempt wrote no relation, event, outbox, or idempotency record: `LOCAL-3` remained `reported/v1` with `duplicate_of_bug_id = NULL`, while the database still contained only the successful `LOCAL-2 -> LOCAL-1` event/outbox/receipt.

Before that authenticated call, one external PowerShell request through the Web proxy returned `401` because that standalone client did not carry the process-local bearer. It performed no write and is recorded as a harness authentication miss, not as the product failure proof or an extra test.
