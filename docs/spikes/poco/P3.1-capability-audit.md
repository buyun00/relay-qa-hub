# P3.1 Poco capability and security audit

- Audit time: 2026-08-25 (Asia/Shanghai)
- Scope: read-only discovery of the authoritative Relay-managed Unity project and its vendored Poco implementation
- External mutations: none; no Relay API/control action, Unity action, Git write, LAN scan, or state-changing RPC was performed
- Overall verdict: the active vendored server has the five required standard read-only RPCs and a `5001..5005` bind fallback, but it binds `IPAddress.Any`, has no authentication, and does **not** contain `PocoListenersBase`, `PocoMethodAttribute`, listener registration, or the Poco RPC `Invoke` branch. It is therefore not Loopback-safe and does not support `qa.snapshot` through the planned listener extension. P3.1 static discovery is complete; the real-runtime/security gates remain open.

## 3. Wire protocol and RPC shape

### Framing

`TcpServer.cs:31-47` buffers a four-byte header and reads it with `BitConverter.ToInt32(buf, 0)`. `:63-73` writes a four-byte `BitConverter.GetBytes` length and explicitly reverses it on a big-endian host. This confirms the intended frame is:

```text
uint32/int32 payload byte length, little-endian | JSON payload bytes
```

However, the implementation is not yet a safe, explicit UTF-8 framing implementation:

- receive and send use `Encoding.Default`, not `Encoding.UTF8` (`TcpServer.cs:45`, `:72`); setting `server.Encoding = Encoding.UTF8` at `PocoManager.cs:53` does not affect `SimpleProtocolFilter`;
- the outgoing header uses `content.Length` (UTF-16 character count), not the encoded byte-array length (`TcpServer.cs:65-73`);
- receive decode assumes the host itself is little-endian; it does not reverse a header on a big-endian host (`:41`);
- zero, negative, oversized, and unbounded buffered frame lengths are not rejected before slicing/accumulation (`:35-53`).

The current JSON serializer escapes non-ASCII (`PocoManager.cs:207-210`), so the five standard response envelopes are normally ASCII-compatible, but that incidental behavior is not a substitute for explicit UTF-8/byte-length and size-limit gates.

### JSON-RPC shape

`RPCParser.HandleMessage` (`PocoManager.cs:212-243`) deserializes an object, requires a `method`, accepts optional `id`, converts optional array `params`, dispatches by exact dictionary key, and returns either:

```json
{"jsonrpc":"2.0","id":<same-id>,"result":<value>}
```

or an error object with `error.code = 1` and the exception string (`:265-291`). It emits JSON-RPC 2.0 responses, but it does **not** validate the incoming `jsonrpc` member/value, restrict the type/range of `id`, or enforce an authentication field. Missing/unknown methods can disclose an exception string.

Recommended standard handshake request for a future strict client:

```json
{"jsonrpc":"2.0","method":"GetSDKVersion","params":[],"id":"<unpredictable-request-id>"}
```

Acceptance must require a bounded valid frame, valid JSON object, exact `jsonrpc == "2.0"`, exact echoed `id`, no `error`, and integer result `6`. Result `6` proves only the standard server identity below; it does not prove listener/Invoke support.

## 5. Security judgement

### Network exposure

The current source fails the required Loopback boundary. `new AsyncTcpServer(port + i)` resolves to `IPAddress.Any`; barring a separate firewall/NAT block, it listens on every guest interface. Static source cannot prove whether a particular APK/device firewall currently makes a LAN connection fail, and no LAN connection was attempted. For the product gate, `IPAddress.Any` is a failure even if an external firewall happens to mask it.

### RPC exposure

The active server registry is materially safer than upstream: it contains hierarchy/screenshot/screen/profiling/version reads and no touch, `SetText`, `SendMessage`, VR rotation, or generic listener `Invoke`. An unknown control method falls into a dictionary lookup error and produces an error response; this is static evidence, not a completed malicious-client runtime test.

There is no authentication. Loopback conversion would remove LAN exposure but would not prevent another app/process in the same OS/profile from reading screenshots or hierarchy. At minimum, this server must remain QA/Debug-only, Loopback-only, and exact-registry-only. Any custom snapshot carrying more sensitive data needs a session-bound credential plus nonce/deadline/replay checks; the real-device threat model must explicitly decide whether the five standard read methods also require an authenticated adapter.

## 6. Runtime probe result

No safe existing runtime was available, so no JSON-RPC request was sent:

- Host `Get-NetTCPConnection` showed no listeners on local ports 5001-5005.
- The connected local MuMu device `127.0.0.1:16384` is Android 15/API 35, but its resumed activity was the launcher; no OZDQP/baloot package matched the installed third-party package list and `/proc/net/tcp*` contained no 5001-5005 listener.
- The Relay workers were inspected only through the configured read-only SMB workspaces. Guest administrative editor logs were not accessible under the current account, and this spike did not invoke PowerShell Direct, Relay control APIs, Unity endpoints, or known worker LAN addresses.
- No LAN scan or targeted LAN connection was made.

Therefore these validation statements are **not** claimed: 127.0.0.1 handshake success, LAN connection failure, actual port fallback, non-Poco-port discrimination, real unknown-control rejection, Mono/IL2CPP behavior, or `qa.snapshot` response.

## 7. Minimum compatible change recommendation

This section is a recommendation only; no Unity/Relay file was changed.

1. **Preserve the current adapter contract first.** P3.7 can support only the five proven methods. Probe configured loopback port first, then de-duplicated 5001-5005, with per-attempt timeout and a total deadline. Continue after connect timeout, invalid/oversized/truncated frame, invalid JSON, wrong `jsonrpc`, wrong `id`, `error`, or a `GetSDKVersion` result other than integer 6. Never infer `Invoke` from version 6.
2. **Bind explicitly to Loopback.** In active `PocoManager.cs`, construct `new AsyncTcpServer(IPAddress.Loopback, port + i)` (the address-taking constructor already exists) and retain the exact five-method registry. Do not change the legacy UWA fork as part of this patch.
3. **Fix the frame implementation at the same boundary.** Use strict `UTF8Encoding(false, true)`, compute the header from encoded byte length, decode little-endian explicitly, reject `length <= 0` and length above a small configured maximum before buffering/allocation, cap accumulated input and output, and close malformed clients. Keep screenshot and hierarchy limits below the future Android client limits.
4. **Do not pretend the listener extension exists.** The smallest auditable compatibility layer is a direct, exact registration of `qa.snapshot` in this fork with a narrow DTO. It should echo `captureId`, enforce session credential + nonce + deadline, cap output, redact by default, and have no reflective method discovery. If the project instead chooses upstream listener compatibility, vendor the three pinned extension files plus the `pocoListenersBase`/listener table/`Invoke` plumbing, then enforce a server-side listener allowlist containing only `qa.snapshot`; generic annotated business methods remain prohibited.
5. **Keep build gating explicit.** Retain the existing Android debug/`OZDQP_AI_TESTING` bootstrap guard, add IL2CPP preservation only for the exact provider/DTO, and produce a provenance-bound test APK. Standard release builds must not start the server.
6. **Rollback boundary.** Implement the change as one isolated Unity-project commit touching only the active Poco fork, its bootstrap/provider, preservation metadata, and focused tests. Rollback is the inverse of that commit plus the matching test APK rollback; Relay configuration and the legacy UWA fork are outside this change.

## 8. Remaining real gates

P3.1 must not be represented as a live capability/security pass until all of the following are captured against a provenance-bound QA APK/build:

1. `127.0.0.1` `GetSDKVersion` handshake succeeds with exact response id and bounded 4-byte little-endian UTF-8 frame.
2. Device Wi-Fi/LAN address connection to each candidate port fails after the Loopback patch; listener inspection corroborates `127.0.0.1`/`::1` only.
3. Port 5001 occupied by a non-Poco service does not misidentify it; the client safely advances through 5002-5005 and stops at the proven server.
4. `Screenshot`, `Dump(true)`, `GetScreenSize`, and `GetDebugProfilingData` return bounded, correctly typed results; timeout/oversize/cancellation degrade without blocking normal capture.
5. `SetText`, touch/input, `SendMessage`, `RotateObject`, generic `Invoke`, and arbitrary method names are rejected by the running server; error responses do not leak stack traces.
6. If added, only authenticated, non-expired, non-replayed `qa.snapshot` succeeds; all other listener names and sensitive/oversized fields fail closed.
7. Mono and IL2CPP QA builds both pass, and a release build proves that Poco never starts.
8. A malicious same-profile client and cross-profile client are tested according to the Android 15/16/17 matrix; Loopback alone is not recorded as authentication.

Until those gates pass, downstream work may implement a no-Poco/standard-five-method fallback, but `G3-ANDROID-APP-READY` remains blocked on Loopback/read-only/authentication/runtime evidence.
