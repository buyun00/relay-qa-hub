## 最新验收边界：代理只调试网页与 APK，不尝试调试 EXE

用户进一步明确：“主对话也不要有任何尝试去调试 exe 的行为，exe 的验收由我进行，他只负责网页和 APK 就行。”本节覆盖下文任何可能允许代理进行 EXE 调试或实际验收的解释。

- 主任务和全部子 Agent 均不得启动、安装、升级、附加调试器、原生点击、截图观察或以进程/日志追踪等方式调试 EXE；不进行桌面通知、EXE 本地 MCP 和桌面更新的实际验证。不得改称诊断、冒烟或配置检查后继续。
- EXE 仅保留必要代码制作、编译/打包与下载产物交付。实际行为和全部验收由用户完成，统一标记“用户自测／代理未执行”，不作为代理交付阻断。没有用户反馈的桌面行为不自行试探复现。
- 代理负责网页和 APK 的功能调试及必要验收，并继续原已授权的后端、LAN、API 与服务端 MCP 配套工作。物理 Android 真机仍由用户自测，代理可以使用可用模拟器。
- 立即停止或转移 EXE 验证子任务；不要为了停止验证擅自关闭已经运行的试用或日常 EXE。所有仍在执行的子 Agent 同步此边界，不再请求用户批准 EXE 测试。

## 最新范围修订：按内网工具交付，停止安全专项扩展

用户在制作过程中明确要求：“这是内网使用的工具，不要管这些安全问题。”本节优先于下文原先为安全加固补充的要求。

- 本次聚焦正常内网使用、项目初始化、固定四位码加姓名登录、分发和部署。不新增复杂鉴权或安全专项，不因这些内容拖延交付。
- 初始化链接的一次性销毁/防重放、额外 CIDR 安全审查、恢复目录 ACL 加固、限速表容量加固以及专门的验收日志安全审查，不再作为本轮必做项或发布阻断项。下文提及的失败限速、短暂冷却等也不再是必须补齐的交付条件。
- 已经完成且正常工作的保护和修复保留；不为移除保护重新改代码或扩大回归。未完成的安全专项从清单中移出，不继续派发安全审查 Agent。
- 项目名和四位码的正常校验、成员正确归属、项目数据分离、初始化业务正确、备份不丢数据、新旧实例并行，仍属于用户要求的功能和运行条件，继续完成。初始化页面按方便负责人使用的简单流程制作，不强求安全凭据生命周期设计。
- 不增加安全发布门禁，不重复全量扫描和安全验收。按尚缺的业务、LAN 部署、EXE/APK 交付及必要新增功能验证收口；用户自测项维持原移交范围。
- 本修订不授权影响旧生产、清除用户数据或向外发送真实密码与凭据。交付资料不主动附带这些信息即可，不因此衍生新的加固任务。

本文件是《项目制与组件化改造方案 v2.1》的增补。冲突处以本次用户要求为准，继续保持项目一级、项目员工与唯一 GM、基础 Bug 管理、按项目启用组件，以及 Web / Windows EXE / Android APK / HTTP API / MCP 同步兼容。

## 3. 产品流程

### 3.1 GM 创建初始化入口

1. GM 在管理网页新建待初始化项目，取得只对应这个项目的初始化链接。
2. GM 将此链接交给项目负责人；由用户自行发送，代理不得代发消息给其他人。
3. 负责人不需要 GM 账号，也不能通过链接看到或修改其他项目、全局设置及其他项目组件。
4. 不新增“项目管理员”等永久身份体系。负责人身份仍为普通项目员工，初始化权限通过这一个项目的专属管理链接承载。
5. 初始化链接使用独立的不可猜测凭据，不使用员工四位码作为管理口令；GM 可以撤销和重新生成。默认初始化提交成功后关闭该次写入入口，后续重新初始化由 GM 重新签发。已有项目内人员管理保持现状。

### 3.2 项目负责人初始化

管理页只展示本项目需要填写的内容：

- 项目名称：支持中文和常见英文名称；用于员工输入和项目识别。
- 项目 Logo：上传、预览、替换和清除；未上传时提供默认图标。首版以项目页面和应用内品牌展示为准，不要求为每个 Logo 重编译客户端图标。
- 初始用户：支持一次输入多个人名，例如逐行粘贴；规范化去重，提交前预览，重复提交不产生重复成员。
- 项目验证码：系统生成且显示四位数字，可复制；保留前导零，例如 `0042`，不得转换成整数后丢失位数。
- 提交后显示项目名称、员工加入说明、项目入口以及 Windows / Android 下载入口。验证码只在有管理权限的页面显示，由负责人自行传达。

项目名称匹配必须确定，不能同名随机匹配。明确统一的首尾空白与大小写等规范化规则，同一部署内用于加入的名称应唯一。保留稳定的 projectId，改名不得换项目 ID 或割裂已有 Bug、成员、附件、草稿。

如果已存在重复名称，迁移时给 GM 明确冲突处理入口；不要静默修改历史项目名或把不同项目合并。

初始化状态有明确的“未完成 / 已可使用”。未完成项目不接受普通员工加入。名称、Logo、初始名单、验证码应一致提交，失败不能留下可进入但配置不完整的项目。

### 3.3 员工加入和登录

所有端使用同一条业务规则：

1. 首次使用选择或填写服务器地址；分发包默认使用本次局域网部署地址，并允许之后在设置中修改。
2. 填写项目名称和四位验证码；允许分享入口预填项目名称，但不把验证码放入 URL、二维码或普通下载清单。
3. 校验成功后填写姓名，或在同一表单中一起提交三个字段。
4. 姓名已存在时复用当前项目员工；不存在时，默认自动创建项目员工并加入当前项目。初始用户名单是预置，默认不作为禁止新员工加入的白名单。
5. 不新增员工密码、短信验证码、审批或账号注册表单。代码验证、成员关联与登录在服务端完成，客户端不能自行声明已经加入。
6. 重复点击、重试或并发加入应得到同一个有效成员关系，不能产生多个同名员工。跨项目同名不自动合并身份，不因为相同姓名公开另一项目。
7. 加入后只显示当前人员已经建立有效关系的项目。加入另一个项目时，同样校验该项目名称和四位码。
8. 在正常会话和已加入项目记录仍有效时，不要求每次启动都重新填三个字段；退出、新设备或加入新项目时按规则验证。停用成员不允许靠“首次加入”路径自动复活。

说明：用户暂未另外选择时，按第 4 条“正确项目码 + 新姓名即可自动加入”实施。若用户随后明确选择名单限定，应同步调整本文件和实现任务，避免同时实现两套可配置鉴权模式。

### 3.4 四位码的边界

- 四位码是每个项目固定的共享加入口令，首次生成后持久保存，服务重启、客户端升级、修改 Logo/名称、刷新页面和数据库迁移都不能自动更换。
- 如需处理泄漏，提供 GM 明确发起的手动重置；不做定时轮换、短信或一次性口令。重置语义在页面说明；首版可仅影响新的加入/登录，不静默清理历史数据和已建立成员关系。
- 普通访客不能获取全项目目录、项目成员姓名或验证码，也不能通过项目 ID、旧短码、二维码或原姓名登录接口绕过校验。
- 项目不存在和验证码错误给出统一、可理解的提示，不提供匿名项目搜索和自动补全。先成功验证再展示项目内部信息。
- 四位码只有一万个组合，不能承诺“绝对猜不到”。保持内部使用的简单方式，同时在服务端加入轻量失败限速和短暂冷却；不增加复杂角色或作用域配置。避免一个恶意来源永久锁死整个项目。
- 验证码和管理凭据不得进入公开接口响应、日志、埋点、Git、普通下载页或客户端安装包；管理页确有必要显示的四位码通过专属管理流程取得。

在现有 Web 和 GM 管理基础上扩展，避免另建一套不相干的管理系统。

| 页面 | 面向谁 | 必须提供 |
| --- | --- | --- |
| GM 项目管理 | 唯一 GM | 创建项目、初始化状态、初始化链接、四位码管理、已有项目与组件设置 |
| 专属初始化页 | 获得链接的项目负责人 | 名称、Logo、初始用户、验证码展示、保存反馈 |
| 项目交付信息页 | 当前项目管理流程 | 员工加入说明、局域网入口、EXE/APK 下载与版本信息 |
| 普通登录页 | 员工 | 服务器地址、项目名、四位码、姓名、明确错误和重新连接入口 |
| 已登录项目页 | 有效项目成员 | 正确名称和 Logo、已有项目切换、原人员管理及当前项目组件 |

Windows 和 Android 优先使用同一套可配置通用客户端，通过登录选择项目，避免每新建一个项目就必须编译一份 EXE/APK。“项目差异”首先来自服务端项目配置、Logo、组件和可分发的连接预设；若保留单独差异包，也必须支持上述项目名和验证码流程。

管理网页中的下载必须是真实可下载、可安装的当次交付产物，禁止仍引用 127.0.0.1、开发者的用户目录或日常生产更新通道。安装器配置和客户端数据目录必须适用于其他 Windows 用户；不能携带 `C:\Users\lin0` 下的运行目录作为收件人本地 profile。

项目 Logo 的文件归属、大小和支持格式要受控；更换一个项目的 Logo 不影响其他项目。下载入口、更新清单、API/资源/WebSocket 地址使用同一个明确的部署基址规则。

## 5. 局域网基础设施

### 5.1 地址识别与稳定地址

- 在部署配置或管理网页提供“检测局域网地址”功能，返回宿主机有效 IPv4、网卡、默认网关、当前是否 DHCP、推荐地址与可访问 URL。
- 检测必须在服务器执行，不能把访问者电脑的地址当成后端服务器地址。
- 根据接口状态、默认路由、有效地址和路由优先级推荐。排除 loopback、APIPA 和仅供模拟器/内部交换机的不可达网络，但保留承载实际办公网络的 Hyper-V 外部交换接口。
- 多候选地址时允许 GM 选择并保存；提供手动覆盖。普通员工只看清楚的服务器地址或连接失败提示，不展示复杂网卡信息。
- IP 变化要能检测并提示，支持修改公布地址后重新生成链接和客户端连接配置；不能继续默默发布失效链接。
- 当前 `10.100.5.157` 来自 DHCP。优先由路由器对宿主机做地址保留，以稳定这个地址。没有路由器管理权限时，先完成当前地址可用的独立部署和地址修改能力，将“地址保留”明确列为用户/网管操作；不可虚称已固定。
- 不擅自切换 DHCP、改宿主机 IP、重启网卡或修改默认路由，以免影响正在运行的生产服务。需要管理设备的唯一外部动作可以交接，但不能以此停止其他已授权制作。

### 5.2 服务入口与隔离

- 新任务使用独立工作树，并为本轮 LAN 交付使用独立的运行目录、端口、数据库、附件、队列、配置、日志、备份、发布目录和客户端身份/更新通道。
- 保留日常生产和此前本机试用实例。端口由实施时检查空闲后选定并写入交付文档，不能覆盖 4319/4174/4320 或现有 4639/4640/4641/4642。
- 明确区分内部监听地址和对员工公布的基址。保留旧 loopback 试用模式；新增明确的 LAN 部署配置，不全局删除原隔离保护。
- 可让 API 保持本机监听，由 Web/代理提供同源 API、附件、下载和 WebSocket；也可复用现有服务形成等价、易维护的入口，避免为了部署额外引入庞大服务体系。
- 浏览器来源校验、Cookie、原生客户端请求来源、下载/更新清单、HTTP API 和服务端 MCP 都要匹配真实 LAN 入口，不能仅让首页能打开。
- 用户已授权完成办公室内部共享所必需的新增监听和 Windows 防火墙规则。规则仅针对本轮实例需要的程序/端口和本地子网；不得关闭防火墙、全端口放行、开放公网端口转发或改变生产规则。
- 识别当前网络配置文件；不能假定必须是 Private 才生效，也不能为了方便切换整张网卡的网络配置。按实际配置文件建立窄范围规则。
- 服务端 MCP 面向授权内部调用者；本地 EXE MCP 继续只监听本机，不把桌面文件操作能力直接开放给局域网。

### 5.3 常驻、备份与恢复

- 提供可重复执行的安装/启动/停止/状态/卸载部署脚本，操作对象必须是新实例。卸载常驻任务不删除数据。
- 配置开机启动、异常恢复、日志落盘及轮转、API readiness 检查；使用后台窗口，进程身份识别不能只凭 node.exe 名称。
- 启用独立自动备份，覆盖一致的 SQLite 状态、附件与恢复必需配置。敏感配置仍留在受限本地目录，不进入普通下载目录。
- 备份保留沿用已确定的项目习惯并保持可配置；仅处理新实例自己产生的备份，不触碰生产历史和已有试用证据。至少保留最近成功的可恢复点。
- 完成一次新实例备份和独立目录恢复验证；不通过恢复到正在使用的实例证明可恢复。
- 交付中明确说明：本机作为共享服务器需要保持开机、联网；断网/休眠时客户端应清楚提示并保留草稿。
- 不把开发验收中的测试项目、虚构初始人员或测试 Bug 当作正式团队数据发放。真实项目名称、Logo 和人员由初始化页面录入。

- `apps/api/src/parallel-instance.ts` 与 `scripts/project-components/` 中的初始化、启动、Web/MCP 代理、打包和安装器。
- `apps/desktop/src/preview-config.ts`、网络和登录配置；Android 的登录、服务器地址持久化、BuildConfig 和本地项目队列。

必须提供等价的 HTTP 和 MCP 使用路径：项目初始化、加入登录所需 API 与管理动作保持明确；登录/加入得到的现有项目上下文继续支持 Bug 列表、详情、状态、评论、附件等操作。HTTP 与 MCP 复用同一业务校验，不能以“只供 MCP”或“只供前端”形成绕过入口。

普通项目验证码不能换取 GM 权限；已有授权的机器调用机制继续使用，但不能作为匿名加入项目的后门。对旧有项目 ID/短码登录与切换路径逐个检查，新增校验必须在服务端生效。

迁移只能作用于新实例或经明确选择的新版数据，先备份再迁移。保留现有项目 ID、人员归属、Bug、草稿、附件和组件配置；没有验证码的迁移项目由 GM 初始化加入设置，不能默认为所有项目设置相同公开码。

## 7. 客户端兼容要求

- Web、EXE、APK 同步实现项目名/验证码/姓名登录和项目 Logo 展示。
- 支持持久保存和修改服务器地址；首次配置失败有重新设置入口，不把失败视为用户数据需要清空。
- 项目切换、服务器切换时，会话、缓存、通知、离线队列、截图草稿及未上传附件继续按服务器/项目/人员区分，不能错投到新服务器或另一个项目。
- 切换前说明仍有待提交数据并保留原数据；不得清空草稿作为解决办法。
- 通用安装包不包含 GM 凭据、初始化链接凭据或项目加入码。
- EXE 和 APK 的下载和更新清单、版本及哈希与交付产物一致；局域网客户端从正常入口可获取更新。
- 保留各项目原有功能开关；基础 Bug 管理独立可用。初始化负责人不能借初始化链接启用全局未授权组件。

## 8. 实施顺序与验收收口

1. 新工作树基于已完成组件化提交建立新 `codex/` 工作分支，复制本需求文件并记录新实例清单。
2. 完成数据迁移、初始化/加入业务及 HTTP/MCP 共用校验。
3. 完成 GM/负责人管理页、分发页，以及 Web/EXE/APK 登录和服务器配置。
4. 完成 LAN 入口、地址检测、常驻、防火墙、备份、软件下载及更新配置。
5. 构建可分发 EXE/APK，部署独立 LAN 实例，执行本次新增功能的有界验收。
6. 修复本次发现的真实失败，更新交付清单，提交并非强制推送新工作分支，核实本地与远端 SHA。

允许按用户既有授权使用 GPT-5.6 Luna 子 Agent 并行处理独立验证，主任务协调、修复、汇总；主任务不重复执行所有验证，不开启多轮无新变化的全量验收。

| 验收项 | 必须证明 | 边界 |
| --- | --- | --- |
| 地址检测 | 当前办公网口能被识别、支持多候选/手动覆盖、DHCP 状态真实显示 | 本机回环请求不算其他设备连通 |
| LAN 入口 | 使用公布 LAN 地址完成真实网页登录、请求、附件和通知；若有可用独立网络端点，补连通检查 | 无第二台可控设备时明确记录，不假造“办公室所有电脑已验证” |
| 初始化 | A/B 两个项目独立初始化名称、Logo、名单；重复提交不重复 | 测试项目明确标记并保留必要证据 |
| 加入与保密 | 正确码可加入；错误码拒绝；新姓名自动创建；旧登录入口不能绕过；匿名无项目/人员全量目录 | 不把四位共享码描述为实名认证 |
| 项目数据 | A 看不到 B，跨项目读写拒绝，成员停用有效，同名不意外合并 | 继续原基础 Bug 行为 |
| HTTP/MCP | 同一加入/会话上下文可列单、改状态、评论和取附件，错误项目拒绝 | 不恢复旧外部集成验收 |
| 发布配置 | EXE/APK 确实生成、入口下载哈希一致，地址和配置适用于其他用户 | 不以旧版安装包冒充本次产物 |
| 常驻恢复 | 新实例注册任务正确；新实例服务受控重启后 ready；备份可恢复 | 不重启整台主机、不触碰旧生产 |
| Android | 可用模拟器覆盖新增登录、配置和项目切换；新 APK 交付 | 物理 Android 仍由用户自测 |
| Windows EXE | 完成开发、构建、配置和安装包交付 | 用户已明确所有 EXE 实际测试自行负责，代理不得再操作 EXE 做原生点击/安装/升级/通知/local-MCP 验收 |

用户自测继续包含：Windows EXE 全部实际操作、物理 Android、真实打包、单次打包上传、真实增量上传发布、Relay AI 制作交付、青鱼同步闭环。标“用户自测／已移交，代理未执行”，不得当作代理未完成阻塞，也不得标 PASS。

完成判断：本次代理范围实现和部署可用、有当次交付包、必要新增验证通过、远端分支同步、用户自测项和真实外部限制写清。不能把用户自测当作继续无限验收的理由；也不能仅凭端口监听、源码提交或构建成功宣布其他电脑已可使用。
